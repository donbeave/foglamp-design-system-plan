## Overview

The portal composes extracted components, MDX, a generated registry catalog, and Fumadocs Story. Stories have two independently connected channels: Fumadocs owns argument controls and iframe argument messages; the portal owns surface/theme messages. Registry provenance is separate from both, keyed by the component identity stored during registration. Shared runtime changes must preserve those relationships while story and documentation writers work on distinct files.

## Key Concepts

- A story registration is `defineStory({ id, registryItem, Component, args, frame })`: `apps/docs/src/lib/story.tsx:12` validates the ID, associates the Component with the registry item in a WeakMap, and calls the Fumadocs factory with `/stories/${id}`. The public factory result is `WithControl`, `Frame`, and `_private_.component`; it does **not** expose default args (`apps/docs/node_modules/@fumadocs/story/dist/client/compiled.js:37`, `compiled.d.ts:43`).
- Vite installs `story()` (`apps/docs/vite.config.ts:6`); the library's generated `_generated.controls` is deserialized into a TypeNode and fixed values collapse controls (`compiled.js:10`). `initial` and `fixed` may be values or functions, and fixed values merge over initial (`compiled.js:17`; `compiled.d.ts:27`). Provider initializes from the first preset and resets engine data on selecting a variant (`provider.js:11`). Thus standalone defaults must use the same resolution/merge behavior, not just `args.initial` or component defaults.
- Registry classification comes from source header tags in `packages/registry/scripts/build-registry.ts:299`, then `registry.json` entries and generated public story catalog (`:421`, `:435`, `:465`). Current generator fabricates one `inspirationPath` for every Tailrocks original (`:306`); `StoryProvenance` currently requires an upstream *or inspiration* URL (`apps/docs/src/components/provenance.tsx:17`). The required absent-upstream original state therefore needs coordinated generator, runtime, sync, and verifier changes, rather than an invented upstream link.

## How It Works

1. Fumadocs derives a TypeNode from the story component signature; `FoglampStoryPanel` wraps `StoryProvider` (`story-panel.tsx:22`). `Controls` unwraps intersection nodes, maps object properties to enum/boolean/string/number controls, and writes the data engine (`:119`). Nested `args: Args` produces one object control instead of real controls; progress illustrates this and additionally changes unused local state while rendering `args.value` (`stories/primitives/progress.story.tsx:6`). Story authors must expose direct props and wire their interactions; controls cannot fix an ignored prop.
2. `useStoryFrame` posts `fumadocs-story:args` to the iframe and responds to ready (`provider.js:65`). The iframe's library `StoryFrame` subscribes, verifies parent and same origin, initially returns null, and renders Component only after args arrive (`client/frame.js:5`). `/stories/$` imports the module dynamically and only renders `story.Frame` (`routes/stories/$.tsx:5`). For standalone routes viable candidates are: expose Component plus first-preset resolved args in the local wrapper and directly render it only when top-level; or seed a self-message after Frame subscription when `window.parent === window`. The first avoids timing races and keeps embedded messages intact; the second preserves Frame behavior but must wait for subscription and prevent self-defaults from overwriting embedded controls. Both must match fixed/initial merge semantics and support function values. No defaultArgs exist on today's story object.
3. Portal `FramePreview` uses a separate origin/source/sequence-checked `foglamp-story:appearance` and ready/theme-state handshake (`story-panel.tsx:89`, `story-frame.tsx:19`). Initial state is hardcoded light; Dark Lift sets only background (`story-frame.tsx:25`). Treat inherited docs theme and explicit workbench override as separate state: follow global theme until the user explicitly chooses Light/Dark; after override, global changes do not silently defeat it. Dark Lift should affect effective preview tokens/foreground while selected, without mutating the stored selected/inherited mode; leaving it restores that mode. Ensure acknowledgements report actual effective state without feeding a temporary Dark Lift override back as the user's persistent selection.
4. Fixed-width frames scale from viewport width, initially zero, and hide overflow (`story-panel.tsx:73`, `:114`); unscaled frames default to 320px. Centered iframe wrapper consumes 64px and lacks full width (`routes/stories/$.tsx:29`). Story-specific frame dimensions are necessary for viewport-dependent layouts; auto-height requires measuring content after render and changes, bounded fallback for tall/dynamic content, and a deliberate scrolling iframe for scroll-triggered content such as CTA. Avoid treating scaled iframe viewport height as its intrinsic content height or disabling inner scrolling needed by motion. Establish a single ownership boundary for resize/message protocol before story writers add dimensions.
5. Docs loader pulls page metadata and MDX body (`lib/source.ts:4`, `routes/docs/$.tsx:10`); `DocsTitle` and `DocsDescription` precede MDX (`:27`). Body headings/descriptions therefore duplicate shared chrome. `scripts/docs-provenance/sync.mjs:24` maps each story's literal registryItem to catalog metadata, requires exactly 167 and injects provenance into each MDX (`:44–74`). A doc cleanup alone is not durable until sync and `scripts/provenance/verify-mdx.mjs` are updated together. Workbench currently adds both a provenance aside and another footer (`story-panel.tsx:62`), on top of MDX copies. Keep one accessible compact workbench provenance element with all required creator links and use shared docs layout for other page credits.
6. Homepage `index.tsx:47` composes Navbar, callout, full tribute, hero, workbench, cards, CTA and Footer. Navbar gets Framerock text but its nested mark remains upstream; Footer gets default branding (`:58`, `:90`). Full SHA and flex gaps are in callout/card (`:60–68`); hero precedes interactive content directly (`:74–75`). `app.css:5` loads source globals/effects before Fumadocs neutral/preset; `[data-source-surface]` restores source border/foreground only on home and story bodies (`app.css:64`, `__root.tsx:27`). Docs workbench lacks that scope. Geist Mono fallback uses Arial and fixed search shortcut widths (`app.css:43`, `:82`).

## Where Things Live

- Story runtime owner: `apps/docs/src/lib/story.tsx`, `lib/story-frame.tsx`, `components/story-panel.tsx`, `routes/stories/$.tsx`, and shared CSS. Story owners: disjoint `.story.tsx` files and fixtures; coordinate shared fixtures with one owner. Docs owners: disjoint MDX category directories; shared sync/generation and route layout each have one owner. Registry owner: `packages/registry/scripts/build-registry.ts` and generated catalog/payloads. No shared writes: freeze the runtime registration/frame contract before story workers land, and freeze catalog/source-classification schema before provenance/docs generation. Integrator alone runs generators after source and MDX work lands.
- API tables must derive from **target package module exports and their declared props**, not all story imports or fixture props. The current `scripts/docs-provenance/sync.mjs` only maps story-to-registry and injects credits; it does not generate API tables. `build-registry.ts` generates provenance/catalog, not an authoritative typed public API. Any new extraction must resolve the registry item's actual source module, discriminate its exported symbols, and verify descriptions against component behavior; use per-symbol overrides for ambiguity rather than name-only prop dictionaries.
- Branding render inventory: portal homepage passes `brandName="Framerock"` but Footer takes default (`routes/index.tsx:58`, `:90`); reusable `icons/logo.tsx:28` and `blocks/marketing/chrome/logo.tsx:28` each compose a duplicated `BrandMark`, defaulting to Foglamp. `icons/brand-mark.tsx:17`, `blocks/marketing/chrome/brand-mark.tsx:17`, and `widgets/leaf/scan-brand.tsx:31` contain visible marks; story routes explicitly display them (`stories/widgets/{logo,brand-mark,scan-brand}.story.tsx:2`) and instrument-empty-state uses the marketing mark (`stories/blocks/instrument-empty-state-block.story.tsx:3`). Navbar carries Foglamp aria-label (`navbar.tsx:159`); fixtures use project name/domain (`stories/blocks/fixtures.tsx:14`), embed story uses a Foglamp slug and demo values include Foglamp keys/domains (`stories/widgets/{copy-button,animated-api-key,sunset-card}.story.tsx`). These are starting points, not a proof of exhaustive rendered coverage: search component defaults, SVG/assets, registry outputs and all demos after regeneration. Preserve `FoglampHUD`, route IDs, message keys and registry IDs where compatibility requires unless their visible rendering is product branding; preserve all factual upstream and legal references.

## Gotchas

- Fumadocs Frame's module-level args state and asynchronous subscription mean a naive self-post may fire before listener registration or leak args across route changes; test standalone and embedded navigation, preset resets, reload and multiple workbenches.
- `storyRegistryItems` keys by Component identity, so reusing one Component for multiple registry items can overwrite the mapping. Direct external URLs are accepted in `defineStory`, but the workbench currently still requires a catalog entry (`story-panel.tsx:37–39`).
- The promised single provenance footer must still expose Gustavo Fior (@gustavo-fior), Abdul Haidar, Foglamp Labs and foglamp.dev. Keep factual pinned upstream link where real, and identify originals explicitly without a fabricated inspiration path.
- Branding addendum supersedes the old request to restore the Foglamp mark/default wordmark, but not restoration of reusable DOM purity/BrazilFlag or creator attribution. A distinct Framerock mark is required; changing only text leaves the upstream mark visible.
- No browser behavior was executed in this ground-only phase; stated clipping, contrast, and interactions are traced from code and user review, not independently measured here. Later sign-off must test real frames, mobile hero animation, docs routes, and generated registry payloads.
